# 音色克隆（从参考音频造一个专属嗓子）

## When to Use

- 用户丢来一段音频或视频链接（抖音/B站/YouTube 分享链）说「用这个克隆 XXX 的声音」。
- 要给某个人设（助手、角色、数字人）**固定一个音色**，之后每条内容都用它。
- 要在几个克隆方案之间选型（本地跑还是调 API、零样本还是微调）。

## Procedure

1. **拿到音频**。分享短链先解析再下；需要 cookie 的平台（抖音这类）先让浏览器打开该页，用 CDP 导出 Netscape 格式 cookie 文件再交给下载器。落盘后统一转成 **16k 单声道 wav** 给 ASR、**32k 单声道 wav** 给克隆当参考。
2. **切出干净参考**（这一步决定成品像不像，见下节）。
3. **先出零样本版本**（5–15 秒参考就够），**同一句演示台词**跑出成品，别用不同的词做对比。
4. **一次交 2–3 个版本让用户挑**：不同参考片段各出一版，命名 `v1/v2/v3`，在消息里写清每版对应原素材里的哪句话。挑不中再换时间段重切，不要自己猜哪个「应该是」。
5. **想更像就走微调**：把同一个说话人 10–30 分钟干净语音按 `音频路径|说话人|语言|文本` 的 `.list` 标注攒起来再训；素材只有一条短片时，零样本先顶上，并如实告诉用户这是上限。

## 参考片段的三条硬要求

- **单人**：多人对话里切出来的片段会让音色混成几个人，必须挑只有一个人在说的连续段。
- **干声（必须真的把人声分离出来，不是「挑一段音乐轻的」）**：短视频素材的伴奏是**全程铺着**的，靠挑「安静段」挑不掉——平台还会把响度压到 0 dB 峰值，所谓停顿处量出来照样 -13 dB。整段先跑一遍 **人声分离**（`demucs --two-stems=vocals -n htdemucs`），只用 `vocals` 轨切参考；分离出的两条轨还能顺手当微调素材。判断有没有残留伴奏**不靠耳朵**：对「应该安静」的那段跑 `volumedetect`（安静处与说话处同量级＝有伴奏），再抽一张 `showspectrumpic` 频谱图看一眼——整图规律的竖条纹就是鼓点。
- **参考要从原始音频切，不要从 ASR 那份切**：给识别器转的 16k 单声道是消耗品，拿它当参考会砍掉高频（听着发闷发毛）。参考统一从原始文件（如 44.1k）切 **32k 单声道**，再过一遍轻降噪：`-af "highpass=f=70,afftdn=nr=10:nf=-35"`。
- **够长且句子完整**：8–12 秒、句尾收住最好；太短抓不准音色，太长会把语气起伏也一起搬走。

## 选型（按显存 + 要不要微调）

| 方案 | 中文表现 | 参考音需求 | 显存 | 备注 |
|---|---|---|---|---|
| **GPT-SoVITS** | 好，**支持微调**（上限最高） | 5 秒–1 分钟 | ~2–4 G | 推理最快，有现成本机部署就先用它；差评集中在幻觉/吞句，调参后可用 |
| **IndexTTS2** | 情感/自然度第一梯队 | 3–5 秒 | ~7.8 G | 内容配音首选，但**8G 以下免谈**；合成慢 |
| **CosyVoice 2/3** | 中文自然、工程最完善 | 3 秒 | ~4 G | 要多装一套链路；流式/方言强 |
| **Fish Speech / S2 Pro** | 情感好 | ~15 秒 | ≥6 G | fine-tune 容易崩，官方建议只用零样本 |
| **F5-TTS** | ⚠️ 中文读错字率高 | 3 秒 | ~3 G | 只适合英文或试验 |
| **ChatTTS** | 口语化但长文崩 | — | 低 | **禁商用** |

决策顺序：**本机已经能跑的那个先顶上 → 要更像就微调 → 显存够再上 IndexTTS2 做 AB 对比**。别为了追新模型把用户机器塞满。

## Pitfalls

- **同一个人的「说话嗓」和「唱歌嗓」必须用同一段参考。** 歌声转换模型（Seed-VC 这类零样本 SVC + `--auto-f0-adjust`）会把输出音高往**参考音自己的音区**拽：TTS 用 8 秒参考（中位 ~297 Hz / D4），唱歌却另切了 20 秒（~243 Hz / B3），结果整首唱低了 6.6 个半音 —— 既不像同一个人，也和伴奏不同调（用户一听就发现："他那个嗓音和他发语音的不一样"）。定嗓时就把这段参考固化成**所有模型共用的唯一参考**；换了模型或用途先比中位 F0，对不上就先对齐参考再谈修模型参数。
- **判断「像不像」要看音高，不要靠耳朵也不只看向量相似度。** `librosa.yin` 量中位 F0 是决定性指标（同一句人声两个版本差几个半音一目了然）；说话人 embedding 的余弦在“同一人、不同参考段”时也在 0.8 上下，分辨不出来。用 chroma 对伴奏做移调会撞八度歧义（同一首歌会同时给出 -11 与 +1 两个等价解），别拿它当依据去移伴奏。
- **别用整段素材当参考**：一段访谈/短剧直接喂进去，音色是几个人的平均值。先切分再选。
- **句子级时间戳不是必需品**：ASR 要带标点模型才给句级时间戳，不值得为它多下一个模型；正确做法是按 VAD 切窗 → **每个窗口单独转一遍 ASR**，拿到的是这段自己的原文，拿来当 `prompt_text` 正合适。
- **`uv`/`pip` 在装了加速器的机器上装依赖会中途断**：报 `cannot decrypt peer's message`，这是 TLS 被劫持，换镜像也一样。装包时把代理环境变量清掉再跑（详见 `local-proxy-resilience` 技能），或直接复用已经装了依赖的那套 venv（很多语音仓库自带 ASR/TTS 依赖）。
- **模型走国内源**：ASR/TTS 权重从 ModelScope 或 HF 镜像拉，别等 HuggingFace 直连。
- **交付音频不能只发文件**：聊天窗口里丢 mp3，用户常常懒得点开，会直接说「放我看看」。**同时在用户电脑上顺序播一遍**（转 wav 用 `Media.SoundPlayer.PlaySync()`：无窗口、不抢焦点），消息里按播放顺序标清版本号。
- **合规线**：自用无所谓；要发公开内容就不要做成「一听就认得出是某位真实博主」的嗓子，AI 生成标注照打，并把这个风险**明说一次**，不要闷着做。
- 训完/试完把 TTS 推理服务停掉——它会常驻吃 2–4 G 内存加显存，用户会在意。

## 定嗓之后：把选中的参考固化成 Hermes 的 TTS 提供方
用户挑中某一版后，不要只用一次就算了 —— 把它变成以后每条内容都能用的默认嗓子：
1. 把选中的那个人声片段拷成正式参考（例如 `Apps/GPT-SoVITS/refs/dafeiyu_voice.wav`），
   并在同目录写一个 `*.json` 存 `ref_audio` / `prompt_text` / `prompt_lang` / 来源说明。
   `prompt_text` 必须是参考音里的**原话**，以后每次合成都要原样带上。
   **这份文件就是这个人的唯一嗓子**：TTS、歌声转换、任何后续模型都从它取，不要再另切一段临时用（自切那段音区往往不同，一用就露馅）。
2. 写一个 wrapper（例：`scripts/tts-dafeiyu.py`）：读文本文件 → 确保 GPT-SoVITS 在 9880 上活着
   （没起就自己 `Popen` 拉起，等端口，约 30–60 秒）→ POST `/tts` → 按 `{format}` 转码输出。
   它同时解决了懒加载问题：服务平时不必常驻（省 2–4 G 内存），只在真的要出声时才起。
3. 注册成 Hermes 的命令提供方：
   `hermes config set tts.providers.<name>.type command` 和
   `tts.providers.<name>.command '<python> <wrapper> "{text_path}" "{output_path}" "{format}"'`
   —— 这两个键不在 schema 里，`hermes config set` 会拒写，**必须加 `--force`**；写完用
   `grep -A6 '^tts:' config.yaml` 核对（`hermes config get` 对这条路径会误报 "Did you mean"）。
   占位符由 Hermes 自己填：`{text_path}`/`{input_path}`/`{output_path}`/`{format}`/`{voice}`/`{model}`/`{speed}`。
4. 验证：`text_to_speech(provider="<name>", ...)` 能直接出声就算接通。默认 provider 别改（命令
   提供方要等模型加载；把这些克隆嗓子留给要发出去的内容，日常回话用快的那个）。
5. **要发成聊天里的“语音条”，走聊天桥接那一侧**：命令提供方返回的是**文件**（`voice_compatible: false`），不会自己变成语音气泡；在 QQ 上要用 OneBot 的 `record` 消息段发送（写法、`file:///` 路径要求、短回复才配音的策略见 `onebot-qq-bridge` 技能的 voice replies 一节）。
6. **合成服务按需启停**：wrapper 负责“没起就拉起”，所以常驻不必要；在意的用户直接提到过内存/耗电，用完就停。
